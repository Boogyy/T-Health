# Техническое задание

## Общая информация

---

### Название проекта

T-Health

---

### Тип проекта

Веб-приложение для контроля здоровья пользователей и взаимодействия внутри сообщества.

---

### Цель проекта

Разработать приложение, которое поможет пользователям вести здоровый образ жизни, отслеживать физическую активность и питание, делиться своими достижениями с другими участниками сообщества и общаться в тематических группах.

---

## Описание проекта

T-Health представляет собой социальную платформу, объединяющую инструменты для учета здоровья и взаимодействия пользователей.

В системе разделяются личные записи пользователя и публичные публикации:

* личные записи о приёмах пищи используются для отслеживания КБЖУ и видны только владельцу;
* личные записи о тренировках используются для ведения истории активности и видны только владельцу;
* рецепты могут быть созданы для личного использования или опубликованы в ленте;
* посты являются публичными публикациями в ленте активности и могут быть обычными текстовыми постами или ссылаться на тренировку, рецепт или достижение.

Пользователи могут:

* публиковать посты;
* делиться рецептами и тренировками;
* вести учет питания;
* вести учет тренировок;
* получать достижения;
* вступать в сообщества по интересам и публиковать посты внутри них;
* общаться в личных чатах 1 на 1.

Интересы пользователя учитываются через фильтрацию публичной ленты по типам публикаций и участие в тематических сообществах.

---

## Scope MVP

В первую версию приложения входят следующие модули:

* регистрация и авторизация пользователей через Keycloak с использованием JWT;
* просмотр, редактирование и удаление профиля текущего пользователя;
* защита REST API на основе JWT и разграничение доступа к личным ресурсам;
* лента активности с постами типов `TEXT`, `WORKOUT`, `RECIPE`, `ACHIEVEMENT`;
* комментарии к постам;
* личные тренировки пользователя;
* дневник питания, учет КБЖУ и дневная сводка;
* рецепты пользователя;
* достижения пользователей;
* сообщества по интересам с публикациями и списком участников;
* личные чаты 1 на 1.

Детальное описание поведения каждого модуля приведено в разделе “Функциональные требования”.

---

## Не входит в MVP

В первую версию приложения не входят:

* сложная рекомендательная система ленты;
* редактирование опубликованных постов;
* отдельные сообщения и чат внутри сообщества;
* административная панель и отдельные административные сценарии;
* достижения за создание постов;
* отдельная сущность для планов тренировок;
* публикация личных записей о приёмах пищи как отдельных постов;
* создание рецепта на основе уже существующей записи питания;
* обмен сообщениями в реальном времени через WebSocket;
* push-уведомления;
* сложная система модерации контента;
* система приглашений для вступления в личный чат.

Эти функции или их аналоги будут реализованы в следующих версиях проекта при необходимости.

## Функциональные требования

### Авторизация и аутентификация

Регистрация и вход пользователя выполняются через Keycloak.

Система должна предоставлять возможность:

* регистрации пользователя через Keycloak;
* входа пользователя по протоколу Authorization Code с использованием PKCE;
* получения JWT access token от Keycloak;
* проверки JWT-токена средствами Spring Security при обращении к защищённым ресурсам;
* определения текущего пользователя по идентификатору `sub` из токена;
* автоматического создания локального профиля при первом обращении к профилю пользователя;
* проверки прав доступа к ресурсам.


### Роли и права доступа

В JWT могут использоваться роли:

* `USER` — обычный пользователь;
* `ADMIN` — роль, предусмотренная конфигурацией безопасности.

Отдельный административный модуль в текущую версию MVP не входит.

Пользователь с ролью `USER` может:

* просматривать, редактировать и удалять собственный профиль;
* создавать, редактировать и удалять свои тренировки;
* создавать, редактировать и удалять свои записи питания;
* создавать, редактировать и удалять свои рецепты;
* создавать и удалять свои посты;
* создавать и удалять свои комментарии;
* создавать сообщества и управлять созданными им сообществами;
* вступать в сообщества, выходить из них и публиковать посты внутри сообществ;
* создавать личные чаты 1 на 1 и отправлять сообщения в них.

Пользователь не может редактировать или удалять чужие личные записи, рецепты, посты и комментарии.

Просматривать историю личного чата и отправлять сообщения могут только участники соответствующего чата.

---

### Работа с постами

Система должна предоставлять возможность:

* создавать текстовые посты;
* создавать посты на основе существующей тренировки, рецепта или достижения;
* создавать тренировку или рецепт одновременно с публикацией соответствующего поста;
* просматривать публичную ленту постов;
* просматривать список собственных постов;
* просматривать конкретный пост;
* удалять собственные посты;
* фильтровать посты по типу;
* получать и создавать текстовые посты конкретного сообщества.

Каждый пост содержит:

* идентификатор;
* тип поста;
* видимость;
* заголовок;
* текст;
* автора;
* дату создания;
* дату обновления;
* ссылку на связанную сущность, если пост создан на основе тренировки, рецепта или достижения.

Типы постов:

- `TEXT` — обычный текстовый пост;
- `WORKOUT` — пост на основе тренировки;
- `RECIPE` — пост на основе рецепта;
- `ACHIEVEMENT` — пост на основе достижения.

План тренировки может быть опубликован в виде текстового поста типа `TEXT`.

1) Если пост имеет тип `WORKOUT`, он должен ссылаться на тренировку текущего пользователя.

2) Если пост имеет тип `RECIPE`, он должен ссылаться на рецепт текущего пользователя.

3) Если пост имеет тип `ACHIEVEMENT`, он должен ссылаться на достижение текущего пользователя.

Видимость постов:

* `PUBLIC` — пост доступен всем пользователям;
* `COMMUNITY` — пост доступен участникам конкретного сообщества.

Если пост имеет видимость `COMMUNITY`, пользователь должен быть участником соответствующего сообщества.

* создавать комментарии;
* получать комментарии поста;
* удалять собственные комментарии.

Каждый комментарий содержит:

* идентификатор;
* текст;
* автора;
* идентификатор поста;
* дату создания.

### Работа с тренировками

Система должна предоставлять возможность:

* создавать тренировку;
* получать список тренировок пользователя;
* получать конкретную тренировку;
* редактировать тренировку;
* удалять тренировку;
* публиковать тренировку в ленте через создание поста.

Каждая тренировка содержит:

* идентификатор;
* название;
* тип тренировки;
* описание;
* дату тренировки;
* продолжительность;
* количество сожжённых калорий;
* дату создания;
* дату обновления.

---

### Работа с приемами пищи

Система должна предоставлять возможность:

* добавлять личную запись о приёме пищи;
* получать историю собственных записей питания;
* получать конкретную запись питания;
* получать записи и суммарные значения калорий и БЖУ за выбранный день;
* редактировать собственную запись питания;
* удалять собственную запись питания.

Каждая запись питания содержит:

* идентификатор;
* название блюда;
* калории;
* белки;
* жиры;
* углеводы;
* дату приёма пищи;
* дату создания;
* дату обновления.

Записи питания являются личными и не публикуются в ленте активности.

---

### Работа с рецептами

Система должна предоставлять возможность:

* создавать рецепт;
* получать список собственных рецептов;
* получать конкретный рецепт;
* редактировать собственный рецепт;
* удалять собственный рецепт;
* публиковать рецепт в ленте через создание поста.

Каждый рецепт содержит:

* идентификатор;
* название;
* описание;
* ингредиенты;
* шаги приготовления;
* калории;
* белки;
* жиры;
* углеводы;
* ссылку на изображение;
* автора;
* дату создания;
* дату обновления.

---

### Работа с достижениями

Система должна автоматически выдавать достижения при выполнении определенных условий.

В текущей версии достижения выдаются за:

* создание локального профиля;
* добавление первой записи питания;
* добавление десяти записей питания;
* добавление первой тренировки;
* добавление пяти тренировок;
* тренировку продолжительностью не менее 60 минут;
* тренировку с расходом не менее 500 калорий;
* получение пяти достижений.

Система должна предоставлять возможность:

* просматривать список доступных достижений;
* просматривать достижения текущего пользователя;
* публиковать полученное достижение в ленте через создание поста.

---

### Работа с сообществами

Система должна предоставлять возможность:

* просматривать список всех сообществ;
* просматривать список сообществ текущего пользователя;
* просматривать конкретное сообщество;
* создавать сообщества;
* редактировать и удалять собственные сообщества;
* вступать в сообщества;
* выходить из сообществ;
* просматривать список участников;
* просматривать и создавать текстовые посты внутри сообщества.


Каждое сообщество содержит:

* идентификатор;
* название;
* описание;
* владельца;
* дату создания;
* дату обновления.

Пользователь, создавший сообщество, становится его владельцем.

Редактировать и удалять сообщество может только его владелец. Владелец не может выйти из собственного сообщества без его удаления.

---

### Работа с личными чатами 1 на 1

Система должна предоставлять возможность:   

* создавать личный чат с другим пользователем;
* получать список личных чатов текущего пользователя;
* отправлять сообщения в личном чате;
* просматривать историю сообщений выбранного личного чата.

Каждый личный чат содержит:

* идентификатор;
* первого участника;
* второго участника;
* дату создания.

Каждое личное сообщение содержит:

* идентификатор;
* идентификатор личного чата;
* автора;
* текст;
* дату отправки.

Отправлять и просматривать сообщения личного чата могут только его участники.

## User Stories

---

### Пользователь

Как пользователь, я хочу зарегистрироваться в системе, чтобы пользоваться приложением.

Как пользователь, я хочу войти в систему, чтобы иметь доступ к своим данным.

Как пользователь, я хочу редактировать профиль, чтобы поддерживать информацию о себе актуальной.

---

### Посты

Как пользователь, я хочу просматривать ленту постов, чтобы видеть активность других участников.

Как пользователь, я хочу создать обычный текстовый пост, чтобы поделиться мыслями с другими участниками.

Как пользователь, я хочу опубликовать свою тренировку в ленте, чтобы поделиться результатом с другими участниками.

Как пользователь, я хочу опубликовать свой рецепт в ленте, чтобы другие участники могли его увидеть.

Как пользователь, я хочу опубликовать своё достижение, чтобы поделиться прогрессом.

Как пользователь, я хочу фильтровать ленту по типу поста, чтобы отдельно смотреть тренировки, рецепты или достижения.

Как пользователь, я хочу удалять собственные посты, чтобы контролировать опубликованный мной контент.

---

### Комментарии

Как пользователь, я хочу комментировать посты, чтобы участвовать в обсуждениях.

Как пользователь, я хочу удалять свои комментарии, чтобы контролировать оставленный мной контент.

---

### Личные чаты

Как пользователь, я хочу начать личный чат с другим пользователем, чтобы общаться напрямую.

Как пользователь, я хочу отправлять сообщения в личном чате.

Как пользователь, я хочу просматривать историю сообщений в личном чате.

---

### Тренировки

Как пользователь, я хочу сохранять тренировки, чтобы отслеживать свою активность.

Как пользователь, я хочу просматривать историю тренировок.

Как пользователь, я хочу редактировать или удалять свои тренировки.

Как пользователь, я хочу поделиться уже созданной тренировкой в ленте.

---

### Питание

Как пользователь, я хочу сохранять информацию о приеме пищи.

Как пользователь, я хочу видеть калории и БЖУ.

Как пользователь, я хочу получать дневную сводку калорий и БЖУ за выбранную дату.

---

### Рецепты

Как пользователь, я хочу создавать рецепты для себя.

Как пользователь, я хочу редактировать и удалять свои рецепты.

Как пользователь, я хочу поделиться рецептом в ленте.

---

### Достижения

Как пользователь, я хочу получать достижения за активность.

Как пользователь, я хочу видеть свои достижения.

Как пользователь, я хочу поделиться достижением в ленте.

---

### Сообщества

Как пользователь, я хочу создавать сообщества по интересам.

Как пользователь, я хочу вступать в сообщества других пользователей.

Как пользователь, я хочу просматривать участников сообщества.

Как пользователь, я хочу публиковать и просматривать текстовые посты внутри сообщества.

Как владелец сообщества, я хочу редактировать или удалять созданное мной сообщество.

## Нефункциональные требования

Проект должен использовать следующий стек технологий:

* Java 17+
* Spring Boot 3
* Spring Security
* Keycloak / OAuth 2.0 / JWT
* Spring Data JPA
* Spring Validation
* PostgreSQL 16
* Flyway
* Swagger / OpenAPI
* JUnit 5
* Mockito
* Testcontainers

Дополнительные требования:

* Все входные данные должны проходить валидацию.
* API должно иметь Swagger/OpenAPI-документацию.
* Ошибки должны возвращаться в едином формате.
* При штатной работе API не должно возвращать необработанные 500-е ошибки.
* Доступ к защищённым ресурсам должен проверяться через JWT.
* Доступ к личным данным должен быть ограничен владельцем ресурса.
* Должны использоваться миграции базы данных.
* Должны быть подготовлены unit-тесты для бизнес-логики.
* Должны быть подготовлены интеграционные тесты с использованием Testcontainers.
* Целевое покрытие тестами — не менее 50%.

## Архитектура

Приложение реализуется по трехслойной архитектуре:

### Controller Layer

Обработка HTTP-запросов.

### Service Layer

Бизнес-логика приложения.

### Repository Layer

Работа с базой данных через Spring Data JPA.

Взаимодействие между клиентом и сервером осуществляется через REST API.

Основные пакеты проекта:

* `controllers` — REST-контроллеры;
* `services` — бизнес-логика приложения;
* `repositories` — Spring Data JPA-репозитории;
* `entities` — JPA-сущности;
* `dto.request` — DTO входящих запросов;
* `dto.response` — DTO ответов API;
* `mappers` — преобразование Entity в DTO и обратно;
* `enums` — перечисления ролей, типов постов, видимости и других фиксированных значений;
* `config` — конфигурация Spring Security, Keycloak Admin Client, OpenAPI и других компонентов;
* `exceptions` — обработка ошибок и пользовательские исключения.
